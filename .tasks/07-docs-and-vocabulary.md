# 07. Docs and vocabulary

## What to build

The words for what the six tasks before this one built.

**CONTEXT.md gains Onboarding Mode**, written the way the terms around it are —
what it is, what it is not, and an _Avoid_ line where there are words to steer
off. What the objective is; that it is reached once, at startup, and cleared
when the wizard finishes; that there is no skip and no re-entry, so deleting the
last Profile mid-run is the settings page's empty state to say. And that it is
not the compose page's **setup card**, which is a draft's own row of pickers and
was here first.

**CONTEXT.md amends Agent Profile** for the unnamed case: a Profile need not be
named, at most one per harness may be unnamed, no two named alike, and an
unnamed one reads as nothing wherever the harness mark and the model say enough
and as **Default** where a name must be shown.

**`adoption.md`'s *once per machine*** — the paragraph at the head of *A day's
work* telling somebody to register their Repos and save a Profile — becomes the
wizard that does it.

**The desktop roadmap's *first-run is the browser's job*** line now points here.
It also still says the settings page edits Watched Paths, which stage 01
retired, so it is stale twice over.

## Acceptance criteria

- [ ] CONTEXT.md carries **Onboarding Mode**, written as the terms around it
      are, and tells it apart from the setup card.
- [ ] CONTEXT.md's **Agent Profile** says what an unnamed Profile is, what the
      two uniqueness rules are, and how one reads.
- [ ] `adoption.md`'s once-per-machine paragraph describes the wizard instead of
      the list of things to do by hand.
- [ ] The desktop roadmap's first-run line points at this stage and names
      nothing that has been retired.
