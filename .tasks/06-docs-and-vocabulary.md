# 06. Docs and vocabulary

## What to build

The words for what the five tasks before this one built.

**CONTEXT.md's Repo entry gains the two rows.** It says today that a Repo is a
repository registered with Verkstead, and that registering can be taken back;
what it does not say is that one can be *made* from the dropdown that lists them,
or opened from it, and that either lands on the same registry the settings page's
own registration lands on — a created one with a `README.md` commit on `main` by
the configured author, and on GitHub as well where a token is saved. It also says
the Repo dropdown is on the compose page; it is on a draft's composer too, and
after this stage the rows are in both.

**CONTEXT.md's Brief entry gains the zero state**, in the paragraphs about the
composer: what the compose page is when the sidebar's list as filtered is empty —
no sidebar, the wordmark and the gear where the pane title goes, the archived
switch pinned to the bottom-left — and that it is a fact about the list rather
than about a first run, so it is left the moment anything is in that list.

**The design doc's UI section records the zero state as settled**, annotated the
way its neighbours in that section are — the same dated form the previous
onboarding stages used when they revised it.

## Acceptance criteria

- [ ] CONTEXT.md's **Repo** entry says a repository can be created or opened from
      the Repo dropdown, and that both land on the same registry.
- [ ] CONTEXT.md's **Brief** entry says what the compose page is when the
      sidebar's list as filtered is empty, and that the state is about the list.
- [ ] The design doc's UI section carries the zero state as settled, annotated
      the way the entries around it are.
