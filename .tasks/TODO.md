# Files on Answers

The human can attach files to the Brief, and every session of the Conversation
reads them from a directory of its own. The same can now be done from the
answer sheet: a file put on an Answer to a Question Set lands in the same
directory, is named to the waiting agent in the Response it reads, and is
listed to every later session under the Set and the Question it answered.

Settled by the grilling: a paperclip on **every Question and Sub-question**,
never on the set-level comment box — icon-only, no border, subdued colour,
sitting inside the free-text field's padding at the bottom right, vertically
centred when the field is one line. A chosen file **goes up the moment it is
chosen**, onto the Set under the Question's label, so its pill comes back from
the record and survives a reload; a × takes it off until Submit, and a Set the
agent locks unanswered keeps what was attached as record. **A file alone is an
Answer**, not Unanswered. Steers stay as they are. The store's second origin
is `answer`, keyed by the Set and the label; the cap, the flat directory and
the counting-up of a taken name are the Brief's. Uploading and removing are
allowed while the Set waits and refused once it has settled or its
Conversation is Closed. The Set view carries each Answer's files, so the
sheet, the Set page, the Timeline and a Share draw the same read-only pills
with sizes, a Share carrying names and sizes only. `verkstead ask` and
`verkstead answers` print an `attachments` list on each Answer holding the
paths the session reads them at; a deferred Set's digest and the relaunched
grilling's summary name them under the decision; every later session's
`# Attached files` listing groups them under the Set's title and the
Question. The sandbox binds the attachments directory at every launch, made
empty where it is missing, so a session blocked on an ask can read a file
attached mid-ask.
